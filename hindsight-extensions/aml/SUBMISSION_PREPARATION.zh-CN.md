| 用途 | 方法与地址 |
| --- | --- |

LLM 供应商地址不是 AML 的 Add / Search 地址。AML 应访问我们部署的记忆服务，再由服务调用模型和数据库。

### 模型与环境配置

- LLM：确定用于事实提取与记忆处理的实际模型，验证结构化输出、延迟、失败行为及配额。GLM-5.3 目前只是讨论过的候选，尚未接入验证。
- Embedding：单独选择模型，记录模型标识、向量维度、批次与文本长度限制。写入与查询必须使用一致的向量配置；更换模型或维度需要重建相关索引。
- Reranker：明确供应商或本地模型、版本、部署资源及最大输入限制，不能仅依赖未记录的默认值。
- 现有环境模板中的模型是配置示例，不是已确认的最终参评方案；私人模型网关也尚未验证可用的嵌入输出。
- API 与独立 worker 都必须收到正确配置。保留 `HINDSIGHT_API_FAIL_ON_EXTRACTION_ERRORS=true`，避免提取失败仍被确认写入成功。
- 按当前适配器配置启用 worker，禁用延迟执行的 provider Batch API。可续跑期间保留操作记录；评测结束后另行清理数据。
- 为 Add 的处理时间配置相容的网关超时。模板中的等待上限为 1770 秒，不能被更短的代理超时截断。

真实密钥通过部署环境或密钥管理服务配置，不写进本文、示例文件、镜像或提交记录。AML 签发的 Eval Key、我们签发的 Memory System Key、模型供应商 API Key 是三类不同凭据。

## 测试与证据准备

| 阶段 | 检查内容 | 需要保留的结果 |
| --- | --- | --- |
| 工程回归 | 鉴权、输入校验、相同请求重放、冲突请求、用户隔离、多片段保存、重启恢复 | 对应提交与 CI 结果 |
| 真实模型小样本 | 使用获准使用的公开或自建数据，检查事实提取、时间关系、跨会话与多跳检索 | 数据来源、配置、错误样例、准确率及单次成本 |
| 压测与稳定性 | 按拟申报并发测试 Add/Search，观察延迟、超时、限流、队列、存储增长及恢复 | 可承诺的并发与容量，P95 延迟和失败率 |
| 公网预检 | 从外部访问健康检查；带专用鉴权写入后立即检索；错误凭据应被拒绝 | 脱敏请求与响应记录 |
| 官方 Smoke | 验证 AML 到服务的接口与端到端链路 | 官方任务标识与结果 |
| 官方 Full | 在冻结版本和足够容量下运行正式评测 | Run/Job 标识、版本记录及审核材料 |

适配器已经通过的工程 CI 使用了脚本化模型响应，不等于真实模型质量验证。项目自己的 AMB 质量评测也不等于官方 AML 分数。具体回归命令见 [README 的 Validation](README.md#validation)。

按[官方模式说明](https://agentmemoryleaderboard.ai/api-guide)，Smoke 不用于公榜；每小时最多一次，每届每赛道最多 30 次。Full 每个 Key 每赛道最多两次，第二次需首次完成满 30 天。应先完成调试与容量验证再使用 Full。

### 本地运行与官方 Smoke

本地可以运行适配器回归测试，也可以启动 API、worker 和数据库，手动验证 Add 后立即 Search。这些属于自己的预检，不会产生官方 Smoke 通过记录。

官方 Smoke 由 AML 平台发起，需要已审核的在线接口和 Eval Key。记忆服务可以运行在个人电脑上，但必须通过稳定的公网地址供平台访问；平台不能直接访问 `localhost` 或内网 IP。若使用公网隧道或反向代理，应检查完整请求转发、鉴权和 Add 长请求超时，并在评测期间保持电脑、网络及 worker 持续可用。正式 Full 前仍需验证整个部署的容量与稳定性。公网端点限制见[官方接入指南](https://agentmemoryleaderboard.ai/api-guide)。

## 版本冻结与正式提交

按顺序完成以下事项；勾选项应由实际结果支持：

- [ ] 确定服务器、模型方案与费用预算。
- [ ] 部署 API、worker、持久化数据库和公网 HTTPS。
- [ ] 完成真实模型测试、公网预检和容量测量。
- [ ] 固定产品版本，保存代码提交、镜像摘要、脱敏配置、模型和检索参数记录。
- [ ] 准备技术来源与改动说明，核对允许公开的信息。
- [ ] 将最终表单内容交给参赛人确认；真实密钥只填官方指定入口。
- [ ] 在 [Evaluation 页面](https://agentmemoryleaderboard.ai/evaluation)提交新 Key 申请，等待审核。
- [ ] 取得 Eval Key 后运行官方 Smoke，修复问题并同步版本资料。
- [ ] 确认 Full 所用版本、接口和容量与申报资料一致，启动正式评测。
- [ ] 保存结果及脱敏运行记录，按官方流程申请结果审核与发布。
- [ ] 评测后按官方期限删除评测数据及衍生副本，记录清理结果。

Full 受理后的版本变更须遵循官方规则，不能因分数不理想替换版本。评测数据不能用于训练或重建数据集；无额外书面许可时，应在任务结束后 30 天内清理。参见[官方接入与数据要求](https://agentmemoryleaderboard.ai/api-guide)。
